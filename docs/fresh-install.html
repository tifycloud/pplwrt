Controlled first flash · Xiaomi AX9000

CompanyWrt
全新安装教程

这是一份现场操作手册：从唯一正确的镜像、刷前门禁、正式写入，到首次启动、企业网络配置和真机验收，一步不少。

基础系统OpenWrt 25.12.5
设备目标AX9000 Darkyun
发布状态RC / 非稳定版

只适用于这一台已核验设备。

官方标准 AX9000 镜像、factory.ubi、历史 CompanyWrt 版本、x86/64 镜像都不能使用。本教程不会改写 MIBIB、U-Boot 或无线校准分区。

01 · 匹配设备身份

先看当前系统。已经运行 CompanyWrt RC2–RC5 时，在 LuCI 上传 RC6 sysupgrade，不再使用 -F；若要完整体验胖胖龙三步首次设置和默认深色主题，先备份并取消“保留设置”。只有仍运行 KWRT、board 为 xiaomi,ax9000 的设备才执行下面的一次性迁移门禁。

现有 CompanyWrt：换一台 Windows 电脑升级 RC6

  1. 从第 3 节 Release 下载并用 PowerShell 校验 RC6；路由器正常重启后，只把 Windows 电脑接到 LAN，网卡保持自动获取地址，暂不接 WAN。
  2. 访问当前管理地址（全新默认 https://192.168.1.1/），进入“系统 → 备份/升级”，先下载配置备份，再上传 RC6 sysupgrade。
  3. 不要使用强制升级；系统必须正常识别 xiaomi,ax9000-darkyun。任何不兼容提示都应停止。
  4. 本次要验证 Liquid 和首次向导，建议关闭“保留设置”；这会清空宽带、Wi-Fi、密码和插件配置。若保留设置，向导可能不会再次出现。
  5. 升级后等待至少 8–10 分钟，重新获取地址并进入“胖胖龙专用路由器”三步向导。第一页直接显示 DHCP/PPPoE，不再要求勾选有线确认；光猫桥接选 PPPoE 并填写宽带账号/密码，光猫已拨号选 DHCP。

开始前必须确认当前路由器是本项目已经采证的 KWRT 设备。它使用暗云 Boot 单 UBI 大分区，当前系统报告 xiaomi,ax9000，迁移后的专属身份则是 xiaomi,ax9000-darkyun。

核验项必须匹配
MIBIB SHA2562d79c1b15b8946af733dba5fff5e33bf3ba18863ed734710bd2a5e48fc469c11
APPSBL SHA25680908e502add45ee6aa7ad83aa16ec2c3c8bf27b572ac0f9c3fe404b94fc0007（两份）
rootfs MTD偏移 0x01180000，大小 0x0e800000（232 MiB）
UBI 卷kernel、rootfs、rootfs_data 位于同一个 rootfs UBI
目标 profilexiaomi_ax9000_darkyun
分区变体darkyun-large-ubi-v1

board mismatch 是有意设计。普通 sysupgrade -T 会拒绝从旧 board 迁往专属 board。只有项目门禁把 MIBIB、APPSBL、MTD、UBI 和升级脚本全部核对通过后，这一次迁移才可使用 -F。

02 · 准备维护窗口

  • 管理电脑用网线直连 LAN；断开联通、移动 WAN 和其他交换网络。
  • 使用稳定电源，最好接 UPS，预留至少 15 分钟无人触碰的时间。
  • 提前确认暗云 U-Boot、串口或已验证的恢复方法确实可用。
  • 离线备份 KWRT 配置、SSH 主机密钥、校准/BDF、MTD 与 boot 环境证据。
  • 备份只用于人工迁移参考，不把整份 KWRT 配置恢复到 CompanyWrt。
  • 密码、订阅、私钥、原始备份不进入 Git，也不发送到公共聊天。

03 · 下载与校验镜像

只从 CompanyWrt RC6 Release 下载下面这个 sysupgrade 文件：

openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin
文件大小19,128,925 bytes
SHA25606ed3b07dd173ae55b3730acd03f7c804164e1587517917fc8b806accee78de0

Windows PowerShell

Get-FileHash .\openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin -Algorithm SHA256

macOS

shasum -a 256 openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin

Linux

sha256sum openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin

64 位结果必须逐字一致。Release 中的 SHA256SUMS、严格 manifest、usign 签名和 GitHub attestation 已通过独立验证；文件名相似不代表镜像可信。

04 · 确认刷前门禁仍有效

RC6 发布检查不能代替目标路由器的现场检查。路由器重启、换过固件或更换设备后，旧的 /tmp 门禁结果全部失效。RC6 Release 同时提供硬件 preflight、first-flash、OTA 公共脚本、公钥、manifest 和签名；必须在本次维护窗口重新运行，确认 MIBIB、两份 APPSBL、MTD、UBI、KWRT 升级脚本、签名、大小、SHA 和 sysupgrade -T -F 全部通过。

门禁通过后会打印本次随机工作目录。正式刷写前，用实际目录名替换 XXXXXX 并再检查一次：

sha256sum '/tmp/companywrt-first-flash.XXXXXX/ota/openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin'

缺少 usign 或路由器重启过，就在这里停止。

/tmp 是内存盘，重启后镜像和门禁结果会消失。当前已采证 KWRT 没有内置 usign，必须由维护者使用已审计的临时工具流程重新执行门禁；不要从未知第三方源安装，不要跳过签名验证，也不要只上传镜像后手工使用 -F。

确认已审计的 usign 可用后，在路由器 SSH 中运行下面的只读门禁。只有出现 FIRST-FLASH CANDIDATE PASSED ALL AUTOMATED GATES 才能继续；脚本不会刷机。

cd /tmp/companywrt-rc6
chmod 0700 ax9000-darkyun-preflight.sh ax9000-darkyun-first-flash.sh ota-common.sh
./ax9000-darkyun-first-flash.sh \
  --manifest ./RELEASE-MANIFEST \
  --signature ./RELEASE-MANIFEST.sig \
  --image ./openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin \
  --public-key ./companywrt-release.pub \
  --expected-version 25.12.5-company.2-rc6 \
  --confirm-version 25.12.5-company.2-rc6 \
  --confirm-sha256 06ed3b07dd173ae55b3730acd03f7c804164e1587517917fc8b806accee78de0

05 · 执行全新安装

确认有线直连、救援可用、电源稳定、路径存在、SHA256 正确，且现场管理员明确同意后，执行唯一的正式写入命令：

sysupgrade -n -F '/tmp/companywrt-first-flash.XXXXXX/ota/openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin'
  • -n 故意丢弃 KWRT 配置，避免旧插件、网络和防火墙污染新系统。
  • -F 只用于这一次已经通过专属门禁的身份迁移，不能当成普通升级参数。

按回车以后：不要关终端、不要再执行一次、不要拔电、不要按 Reset。等待设备自动完成写入和重启，至少给它 8–10 分钟。指示灯行为与 KWRT 不同也不等于失败。

06 · 第一次连接

全新安装默认情况下使用 192.168.1.1。电脑保持自动获取地址，重新插拔网线或更新 DHCP 租约；一个 LAN 口没有地址时可依次尝试其他 LAN 口，仍然不要接 WAN。

https://192.168.1.1/
ssh root@192.168.1.1

首次 HTTPS 使用本地自签名证书，浏览器可能告警。确认目标确实是直连路由器后继续。登录后的第一件事是设置唯一、随机、离线保存的管理员密码：

passwd

然后运行首次 enrollment：

/usr/share/company/enrollment-preflight \
  --expected-version 25.12.5-company.2-rc6

保存系统身份和分区状态：

ubus call system board
cat /etc/companywrt/VERSION
cat /etc/companywrt/build.conf
cat /proc/mtd
ubinfo -a

预期是版本 25.12.5-company.2-rc6、profile xiaomi_ax9000_darkyun、board xiaomi,ax9000-darkyun 和分区变体 darkyun-large-ubi-v1。任何 FAIL 或不一致都要停止接入生产网络。

07 · 按安全顺序配置

  1. 先设置时区、NTP、密码和 HTTPS，并导出第一次干净配置备份。
  2. 用“胖胖龙专用路由器”三步向导配置主 WAN、三射频 Wi-Fi 和管理员密码。第一页直接选择 DHCP/PPPoE，网线提示仅为安全建议，不再阻止继续。
  3. Liquid 默认使用深色主题；概览页直接显示可用内存、实际已用内存及百分比，不需要悬停。
  4. Wi-Fi 从 HE80 开始；HE160 仍是 AX9000 专项测试项。
  5. 先只接联通宽带，验证 IPv4/IPv6、DNS、NAT 和 WAN 入站拒绝。
  6. 再接移动专线：联通用于办公和下载，移动用于服务器及指定稳定上传连接。
  7. 逐个建立 management、office、server、iot、guest VLAN 并测试隔离。
  8. 先审阅 company-network plan；脚本不会自动应用实时配置。
  9. WireGuard 已预装；日志外发、collectd 监控和 SQM 按需安装/配置。移动 100M 的 SQM 需单独测，联通 1G 默认不开。

OpenClash 不预装。固件没有 OpenClash 本体、Mihomo 核心、订阅或 GEO 数据，只准备了基础依赖。先把原生双 WAN/PBR 跑稳，再按 OpenClash 文档独立安装，避免 nftables、DNS、fwmark 和 ip rule 互相抢控制权。

08 · 真机验收

检查项通过标准
启动可靠性连续两次重启和一次断电冷启动正常，UBI 无错误。
管理与防火墙有线 LuCI/SSH 正常；WAN 侧无法访问管理面。
空载内存冷启动 10 分钟、无客户端/插件后运行 /usr/share/company/memory-report --check-idle 必须 PASS，MemAvailable 不低于 70%。
24 小时内存同一空载条件下可用内存下降不超过 5 个百分点，无持续增长的异常进程。
无线2.4G 与两路 5G 的 HE80 稳定；HE160 结果单独记录。
双 WAN联通、移动的地址、DNS、NAT、IPv6、故障回退及上传策略符合设计。
VLAN / PBR五类 VLAN 隔离正确；每条连接只选择一个出口，回程一致。
企业能力WireGuard、日志、监控、备份、恢复和 OTA 检查全部通过。
救援串口/U-Boot/恢复流程与离线文件实际可用。

09 · 无法启动时

等待满 10 分钟后仍无法访问，不要反复断电。只接一台有线电脑，检查 DHCP、192.168.1.1 和各 LAN 口；随后查看串口/U-Boot 输出，按已验证的暗云 Boot 救援流程处理。保留 MIBIB、APPSBL/U-Boot、校准数据和离线证据，绝不为“试一下”覆盖 bootloader 或改刷官方标准分区镜像。

结论

RC6 已达到已采证暗云 Boot 大分区 AX9000 的受控现场测试候选条件。它还不是企业生产稳定版；只有完成首次刷写或升级，并把启动、空载内存、24 小时稳定性、无线、双 WAN、VLAN、安全、OTA 和救援矩阵逐项跑通，才能给出最终生产结论。
