Controlled first flash · Xiaomi AX9000

CompanyWrt
全新安装教程

这是一份现场操作手册：从唯一正确的镜像、刷前门禁、正式写入，到首次启动、企业网络配置和真机验收，一步不少。

基础系统OpenWrt 25.12.5
设备目标AX9000 Darkyun
发布状态RC / 非稳定版

只适用于这一台已核验设备。

官方标准 AX9000 镜像、factory.ubi、历史 CompanyWrt 版本、x86/64 镜像都不能使用。本教程不会改写 MIBIB、U-Boot 或无线校准分区。

01 · 匹配设备身份

开始前必须确认当前路由器是本项目已经采证的 KWRT 设备。它使用暗云 Boot 单 UBI 大分区，当前系统报告 xiaomi,ax9000，迁移后的专属身份则是 xiaomi,ax9000-darkyun。

核验项必须匹配
MIBIB SHA2562d79c1b15b8946af733dba5fff5e33bf3ba18863ed734710bd2a5e48fc469c11
APPSBL SHA25680908e502add45ee6aa7ad83aa16ec2c3c8bf27b572ac0f9c3fe404b94fc0007（两份）
rootfs MTD偏移 0x01180000，大小 0x0e800000（232 MiB）
UBI 卷kernel、rootfs、rootfs_data 位于同一个 rootfs UBI
目标 profilexiaomi_ax9000_darkyun
分区变体darkyun-large-ubi-v1

board mismatch 是有意设计。普通 sysupgrade -T 会拒绝从旧 board 迁往专属 board。只有项目门禁把 MIBIB、APPSBL、MTD、UBI 和升级脚本全部核对通过后，这一次迁移才可使用 -F。

02 · 准备维护窗口

  • 管理电脑用网线直连 LAN；断开联通、移动 WAN 和其他交换网络。
  • 使用稳定电源，最好接 UPS，预留至少 15 分钟无人触碰的时间。
  • 提前确认暗云 U-Boot、串口或已验证的恢复方法确实可用。
  • 离线备份 KWRT 配置、SSH 主机密钥、校准/BDF、MTD 与 boot 环境证据。
  • 备份只用于人工迁移参考，不把整份 KWRT 配置恢复到 CompanyWrt。
  • 密码、订阅、私钥、原始备份不进入 Git，也不发送到公共聊天。

03 · 下载与校验镜像

只从 CompanyWrt RC3 Release 下载下面这个 sysupgrade 文件：

openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin
文件大小21,371,485 bytes
SHA256577bd2f430c6128f40310ad7f939d613023e0f7b05f978997bddf4a4c536df87

macOS

shasum -a 256 openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin

Linux

sha256sum openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin

64 位结果必须逐字一致。Release 中的 SHA256SUMS、严格 manifest、usign 签名和 GitHub attestation 已通过独立验证；文件名相似不代表镜像可信。

04 · 确认刷前门禁仍有效

当前这台路由器已经通过硬件指纹、签名、镜像绑定和 sysupgrade -T -F 只读测试。若门禁后路由器没有重启，验证过的候选仍在：

/tmp/companywrt-rc3-gate-7027353/ota/openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin

正式刷写前再检查一次路由器上的文件：

sha256sum '/tmp/companywrt-rc3-gate-7027353/ota/openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin'

路由器如果重启过，就在这里停止。

/tmp 是内存盘，重启后镜像和门禁结果会消失。必须重新执行完整的签名、硬件指纹和强制测试门禁，不能只上传镜像后手工使用 -F。当前 KWRT 没有内置 usign，不要从未知第三方源随意安装，也不要跳过签名验证。

05 · 执行全新安装

确认有线直连、救援可用、电源稳定、路径存在、SHA256 正确，且现场管理员明确同意后，执行唯一的正式写入命令：

sysupgrade -n -F '/tmp/companywrt-rc3-gate-7027353/ota/openwrt-qualcommax-ipq807x-xiaomi_ax9000_darkyun-squashfs-sysupgrade.bin'
  • -n 故意丢弃 KWRT 配置，避免旧插件、网络和防火墙污染新系统。
  • -F 只用于这一次已经通过专属门禁的身份迁移，不能当成普通升级参数。

按回车以后：不要关终端、不要再执行一次、不要拔电、不要按 Reset。等待设备自动完成写入和重启，至少给它 8–10 分钟。指示灯行为与 KWRT 不同也不等于失败。

06 · 第一次连接

全新安装默认情况下使用 192.168.1.1。电脑保持自动获取地址，重新插拔网线或更新 DHCP 租约；一个 LAN 口没有地址时可依次尝试其他 LAN 口，仍然不要接 WAN。

https://192.168.1.1/
ssh root@192.168.1.1

首次 HTTPS 使用本地自签名证书，浏览器可能告警。确认目标确实是直连路由器后继续。登录后的第一件事是设置唯一、随机、离线保存的管理员密码：

passwd

然后运行首次 enrollment：

/usr/share/company/enrollment-preflight \
  --expected-version 25.12.5-company.2-rc3

保存系统身份和分区状态：

ubus call system board
cat /etc/companywrt/VERSION
cat /etc/companywrt/build.conf
cat /proc/mtd
ubinfo -a

预期是版本 25.12.5-company.2-rc3、profile xiaomi_ax9000_darkyun、board xiaomi,ax9000-darkyun 和分区变体 darkyun-large-ubi-v1。任何 FAIL 或不一致都要停止接入生产网络。

07 · 按安全顺序配置

  1. 先设置时区、NTP、密码和 HTTPS，并导出第一次干净配置备份。
  2. Wi-Fi 从 HE80 开始；HE160 仍是 AX9000 专项测试项。
  3. 先只接联通宽带，验证 IPv4/IPv6、DNS、NAT 和 WAN 入站拒绝。
  4. 再接移动专线：联通用于办公和下载，移动用于服务器及指定稳定上传连接。
  5. 逐个建立 management、office、server、iot、guest VLAN 并测试隔离。
  6. 先审阅 company-network plan；脚本不会自动应用实时配置。
  7. 最后加入 WireGuard、日志外发、监控及备份。移动 100M 的 SQM 需单独测，联通 1G 默认不开。

OpenClash 不预装。固件没有 OpenClash 本体、Mihomo 核心、订阅或 GEO 数据，只准备了基础依赖。先把原生双 WAN/PBR 跑稳，再按 OpenClash 文档独立安装，避免 nftables、DNS、fwmark 和 ip rule 互相抢控制权。

08 · 真机验收

检查项通过标准
启动可靠性连续两次重启和一次断电冷启动正常，UBI 无错误。
管理与防火墙有线 LuCI/SSH 正常；WAN 侧无法访问管理面。
无线2.4G 与两路 5G 的 HE80 稳定；HE160 结果单独记录。
双 WAN联通、移动的地址、DNS、NAT、IPv6、故障回退及上传策略符合设计。
VLAN / PBR五类 VLAN 隔离正确；每条连接只选择一个出口，回程一致。
企业能力WireGuard、日志、监控、备份、恢复和 OTA 检查全部通过。
救援串口/U-Boot/恢复流程与离线文件实际可用。

09 · 无法启动时

等待满 10 分钟后仍无法访问，不要反复断电。只接一台有线电脑，检查 DHCP、192.168.1.1 和各 LAN 口；随后查看串口/U-Boot 输出，按已验证的暗云 Boot 救援流程处理。保留 MIBIB、APPSBL/U-Boot、校准数据和离线证据，绝不为“试一下”覆盖 bootloader 或改刷官方标准分区镜像。

结论

RC3 对这台已采证的暗云 Boot 大分区 AX9000 已达到受控现场首次刷写条件。它还不是企业生产稳定版；只有完成首次刷写，并把启动、无线、双 WAN、VLAN、安全、OTA 和救援矩阵逐项跑通，才能给出最终生产结论。
